# Teaching and problem guidance

Choose a mode from the request: a concept explanation, a hint, a complete solution, a diagnostic, practice, or feedback. A hint request should preserve the opportunity to solve; a complete-solution request should receive a complete solution.

Load the relevant passage. Identify its prerequisites and use tools the student can reasonably understand. Introduce a new theorem or notation with a short explanation before using it. In a lesson, connect a concrete example to the general rule, explain why the method works, and use a brief transfer question to see whether the student can apply it.

For a student's attempt, identify the first incorrect or unjustified step and explain its consequence. Separate arithmetic slips from conceptual gaps. If a student is confused, change the representation or example rather than repeating the same symbolic explanation.

Before presenting a solution, independently check the reasoning, domain restrictions, extraneous roots, equality cases, or arithmetic as appropriate. If a supplied problem has ambiguous notation, clarify the intended statement before solving it.

For practice, select actual book problems only after reading their statements. When generating original practice, check the answer and label it as generated. Use the student's performance to choose the next task: prerequisite repair, another example, a transfer problem, or a harder extension. Supply a full answer key when requested; otherwise stage hints or answers in the format the student wants.

For geometry or graph questions, use the book diagram when it conveys the setup and inspect it visually. When a new diagram would help, make one with the same labels and quantities used in the solution. Distinguish a schematic from a drawing to scale.
